## 1. 为什么采用 Fork

Fork 把上游仓库复制到你的账号，保留来源关联和主分支历史，方便后续同步。以后个人改动提交到自己的仓库，上游贡献者和原始源码版权继续保留。

本次约定：不 @、发评论、发 Issue 或通知原作者。README 保留项目来源与许可信息。

## 2. 本地目录

阅读独立资料副本时，源码位于旁边的 `ZSWatch` 目录；在源码仓库中，学习资料放在 `docs/zh-learning/`。独立副本和仓库内资料内容一致。

推荐关系如下：

```text
upstream → https://github.com/ZSWatch/ZSWatch.git
origin   → https://github.com/h990566354-sudo/ZSWatch.git
```

`origin` 是自己的远端，`upstream` 是原项目。执行 push 前核对目标账号；没有必要强制覆盖任何已有远端提交。

## 3. 后续开发习惯

每个功能开一个明确的分支，提交中说明改了什么、为什么，以及实际如何验证。同步上游之前先保存自己的工作；处理冲突时理解双方变化，不机械选择整份文件。

例如从自己的 `main` 创建 `feature/sim-monitor`，实现功能、验证，再合入自己的主分支。名字只是建议，尚未创建这个功能分支或实现功能。

提交学习资料、源码和必要的验证材料即可；SDK 大量依赖、构建目录、登录凭据和工具安装包留在本地。原项目已经提供相关忽略规则，未来新增文件时仍要检查待提交清单。
